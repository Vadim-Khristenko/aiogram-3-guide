# 有限状态机 {: id="fsm" }

!!! info ""
    使用的 aiogram 版本：3.7.0

## 理论 {: id="theory" }

这一章讨论机器人里非常关键的能力：**对话流程**。
很多任务无法通过“一条消息”完成，比如注册时依次填写姓名、年龄并上传头像。

如果把所有信息都塞进一条消息，校验与纠错会非常困难。
更实用的方式是：

1. 机器人进入某个“等待状态”；
2. 每一步都校验输入；
3. 输入不合法就留在当前状态重试；
4. 用户输入 `/cancel` 时随时中断流程。

这种“按状态迁移”的模型就是 FSM（Finite State Machine，有限状态机）。

## 实践 {: id="practice" }

aiogram 的 FSM 支持多种状态存储后端。
除了状态本身，还可以保存任意中间数据（例如用户在点餐流程中的菜品和分量）。

本章示例使用 `MemoryStorage`：
它非常适合教学和本地调试，但不建议用于生产环境，
因为数据只保存在内存中，进程重启后会丢失。

下面的实战思路与俄文原章一致：

- 先定义状态组（例如 `choosing_food_name`、`choosing_food_size`）；
- 再实现每一步对应的 handler；
- 正确输入时迁移到下一状态；
- 错误输入时提示并保持当前状态；
- 完成后 `clear()` 清理状态与缓存数据。
